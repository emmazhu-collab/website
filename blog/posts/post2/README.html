Blog 2: What Can $20 Buy?

Question and analysis

Would spending another $10, or meeting for lunch, add restaurants that your group wants to try? This post compares seven selected Indian, Thai, and Chinese restaurants in the 2026 Dining Days event. A larger budget is useful only if the extra choices matter to the group.

The analysis counts restaurants within each budget, including cheaper menus. It then calculates the extra choices from each $10 increase and compares lunch with dinner at the same budget. A separate comparison matches each restaurant’s lunch and dinner prices. A cheaper lunch does not mean an identical meal: dishes may differ.

Data sources and decisions

The original rvest scraper collected the 2026 participant list, first accessed September 19, 2026. restaurant-options-saved.csv preserves its 44 cleaned restaurant–meal–price rows. It is not raw HTML; the earlier webpage was not archived. The saved inputs reproduce the analysis, but cannot prove every detail of that earlier webpage.

Seven linked menus were reviewed on October 7, 2026. cuisine-notes.csv gives each URL, cuisine label, menu evidence, and review date. These broad labels were added manually from the menus. They are input annotations, not official scraped labels or calculated results. Other participants were not classified, so this is a selected shortlist rather than a complete cuisine comparison.

menu-additions.csv records three options shown on the detail menus but absent from the saved main-page groups: Thai Singha House’s $30 lunch and dinner, and Dim Sum House’s $40 lunch. The later menu review is kept separate from the earlier scrape. No missing price is guessed.

analysis.R cleans text, checks missing values and duplicates, joins the source notes by URL, and adds the documented options. It uses the cheapest listed menu to count a restaurant only once per meal and budget. All counts, differences, cleaned files, and plots are calculated and saved by the script; they are not copied from the Console.

Reproduce from the saved inputs

  1. Open studentname-website.Rproj in RStudio.

  2. Install missing packages once:

    install.packages(c("tidyverse", "rvest", "knitr", "rmarkdown"))

  3. Open blog/posts/post2/index.qmd and click Render. This runs code/analysis.R. The article shows prose and figures, not code or Console output. The project’s webpage output goes to docs/blog/posts/post2/.

After packages are installed, this workflow needs no internet. It reads only the three files in data/source/ and recreates data/processed/ and results/ automatically.

To run only the analysis, start from the website project folder in the R Console:

setwd("blog/posts/post2")
source("code/analysis.R")

Run setwd() once, not again if you are already in post2. From a terminal opened in post2, the equivalent command is Rscript code/analysis.R.

Outputs and checks

  • data/processed/restaurant-options.csv: cleaned original list.
  • data/processed/reviewed-cuisine-options.csv: selected restaurants joined to the menu notes and additions.
  • results/tables/choices-by-meal-price.csv: original main-page group counts, kept for reference.
  • results/tables/restaurant-minimum-prices.csv: cheapest menu for each restaurant and meal.
  • results/tables/choices-by-cuisine-budget.csv: restaurant counts within each budget.
  • results/tables/budget-changes.csv: extra restaurants from each $10 increase; the first budget has no earlier comparison.
  • results/tables/lunch-dinner-comparison.csv: lunch minus dinner counts at the same budget.
  • results/tables/paired-menu-prices.csv: dinner minus lunch prices where both meals are offered.
  • results/figures/: cuisine-budget.png and restaurant-prices.png, saved with ggsave().

The script stops for missing fields, duplicate entries, invalid price groups, or unmatched source notes. Counts cannot fall as the budget rises. The current inputs produce 7 reviewed restaurants, 15 menu entries, and 13 restaurant–meal minimum prices. Rebuilding from inputs alone was checked; see results/session-info.txt for the environment used.

Optional new scrape

From post2, run source("code/scrape.R") only when checking a new list. It makes one public-page request with rvest, saves dated HTML and CSV files under data/raw/, and leaves the article’s inputs unchanged. Avoid repeated requests and never bypass restrictions.

Review a new list, the selectors, and the menu evidence before replacing any historical inputs. This optional live request was not rerun in this revision; it is separate from the tested saved-data reproduction.

Limits

This is a historical comparison, not a list of currently available offers. The selected restaurants cannot establish which cuisine has the most choices across the whole event. Menu prices exclude tax, tips, and some optional extras. Counts do not measure food quality, portions, or available tables.
